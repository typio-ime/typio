# Developer Setup

This document is for contributors who will modify Typio source code. **If you only want to use Typio**, see the [Getting Started tutorial](../tutorials/01-getting-started.md) instead.

## Requirements

- Rust toolchain (latest stable `rustc` + `cargo`)
- `pkg-config`

Engines (rime, mozc, …) are separate projects; their dependencies (e.g.
`librime`, `protobuf`) are documented in those repositories.

## External dependencies

| Dependency | Source | Resolved version | You need to install it? |
|---|---|---|---|
| **Rust** (`typio-core`) | Cargo | 1.85 or newer | **Yes** — install `rustc` + `cargo` |

System libraries are discovered via `pkg-config`.

### Pure Rust architecture

`typio-core` is a pure Rust crate whose library artifact is named `typio`:

- **Rust** — The core library (`src/`, crate `typio-core`): instance
  lifecycle, config parsing and schema, input-context state, process-engine
  registry and transport, key-event types, logging sink, and string utilities.

The hand-written C headers in `include/typio/*.h` are the ABI contract. Rust
implements the exported C functions and `cargo build` produces both
`libtypio.so` and `libtypio.rlib`.

When modifying Rust code, edits are picked up automatically on the next `cargo build`.

## Clone and build

Use a debug build when editing code:

```bash
cargo build
```

For an optimized release build:

```bash
cargo build --release
```

## Run tests

```bash
cargo test
```

For an ASan build you can use the Rust nightly toolchain with `-Zsanitizer=address`:

```bash
RUSTFLAGS="-Zsanitizer=address" cargo +nightly test
```

## Optional: build the compose engine

```bash
cd ../typio-engine-compose
cargo build
```

## Build C engines against the in-tree libtypio

C/C++ engines (rime, mozc, …) link `libtypio.so` for engine-facing symbols
(`typio_instance_*`, `typio_config_schema_*`, …). During development you do
**not** need to install `libtypio.so` system-wide — point the engine's build
at the in-tree artifact and the engine loads it via a baked-in `RUNPATH`.

The `typio-engine-abi.pc` file generated by `build.rs` declares
`libdir=target/<profile>`, but `cargo build` of the host only drops
`libtypio.so` at `target/<profile>/deps/`. Build `typio-core` directly so the
cdylib lands where the `.pc` file expects:

```bash
cargo build -p typio-core            # debug  → target/debug/libtypio.so
cargo build --release -p typio-core  # release → target/release/libtypio.so
```

Then configure the engine's Meson build with `PKG_CONFIG_PATH` pointing at
the in-tree `.pc` file, compile, and point the host at the engine build dir:

```bash
PKG_CONFIG_PATH=$PWD/target/debug \
  meson setup ../typio-engines/typio-engine-rime/build ../typio-engines/typio-engine-rime
meson compile -C ../typio-engines/typio-engine-rime/build
./target/debug/typio --engine-dir ../typio-engines/typio-engine-rime/build -v
```

No `sudo`, no install — the resulting engine binary records a `RUNPATH` into
`target/<profile>/` and resolves `libtypio.so` from there at runtime.

### Keep the in-tree libtypio fresh

Re-run `cargo build -p typio-core` after every `typio-core` change. Building
the host alone only refreshes `target/<profile>/deps/libtypio.so`, which the
`.pc` file does not point at; the engine keeps loading whatever sits at
`target/<profile>/libtypio.so`, so a stale copy there can mask edits.
